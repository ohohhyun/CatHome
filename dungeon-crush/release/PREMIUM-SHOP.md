# 2.14.0 외형 · 펫 상점

이번 빌드는 결제 구축 전의 무료 테스트 상점입니다. 상품별 판매 예정가는 **9,900원**이며, 현재 구매는 실제 청구·골드 소모 없이 테스트 보유권만 저장합니다. 결제 서버나 Google Play Billing을 연결하지 않았습니다.

## 상품과 미리보기

6직업 각각 5벌, 총 **외형 30개**와 **펫 10종**을 제공합니다. 외형은 의상과 무기, 전신 이동·공격 애니메이션, 해당 콘셉트의 스킬 효과를 함께 바꿉니다. 상품별 고유 SKU를 유지합니다.

| 컬렉션 | 외형과 효과 콘셉트 |
| --- | --- |
| 성야의 선물 | 크리스마스 벨벳·털 장식·축제 무기, 눈꽃·종·선물·순록 |
| 용염의 맹세 | 흑요석 용갑·잿불 무기, 용염·불꽃·용 문양 |
| 월영의 서약 | 남빛 비단·달빛 은장식, 초승달·별·월광 |
| 천공의 심판 | 백금·오로라 수정·천공 장식, 날개·빛·천공 문양 |
| 심해의 계약 | 심해 청금석·청동·산호 장식, 파도·해류·심해 문양 |

크리스마스 외형은 **모든 직업에 1벌씩** 포함합니다. 펫은 성야의 꼬마 순록, 선물 배달 펭귄, 잿불 아기용, 달빛 여우, 여명 그리핀, 심해 수달, 태엽 부엉이, 별빛 해파리, 숲의 등불 거북, 홍옥 고양이입니다. 앞의 두 펫도 크리스마스 상품입니다.

메인 메뉴와 마을의 ‘외형·펫’에서 엽니다. 캐릭터·컬렉션·보유 필터, 판매 예정가, 보유/장착 상태를 표시합니다. 구매 전 대기·걷기·3연계 공격·9개 스킬·점프·대시, 방향을 미리 볼 수 있습니다. 낮은 가로 화면은 동작 선택 목록과 독립 스크롤을 사용합니다. 펫은 걷기/부유·대기·인사 동작이 있습니다.

## 외형별 형태와 휴대폰 UI

각 외형은 투구·상의·하의·등 장식·망토·무기를 콘셉트에 맞게 제작했습니다. 크리스마스 6벌과 펫 10종은 유지하며, 나머지 24벌은 아래 실루엣으로 이동·공격 48시트를 다시 제작했습니다.

| 직업 | 용염 | 월영 | 천공 | 심해 |

휴대폰 가로 화면에서는 상점 구매·장착·해제 버튼을 상품 목록 스크롤과 분리해 화면 안에 유지합니다. 상품 카드를 두 열로 키우고, 목록 전체가 한 방향으로 스크롤됩니다. 작은 화면·노치/하단 여백과 1.4배 글자에서 버튼 가림과 글자 겹침을 검사합니다.

가방·상점·대장간·스킬의 주요 조작, 확인창, 닫기와 마을 메뉴는 최소 44px 터치 높이를 적용합니다. 작은 글자와 장비 카드를 키우고, 설명과 목록은 독립적으로 스크롤합니다. 설정 슬라이더도 터치 높이를 확보하며, 확대 글자의 긴 메뉴 설명은 버튼 높이에 맞춰 늘어나고 메뉴 안에서 스크롤됩니다.

## 구매·장착·기록

- ‘무료 테스트 구매’ 확인 후 받습니다. ‘테스트 상품 모두 받기’도 별도 확인합니다. 중복 구매는 보유 상품을 추가하지 않습니다.
- 외형은 해당 직업에게 장착합니다. 펫은 같은 저장 기록 안에서 공유하여 직업별로 하나씩 선택합니다. ‘기본 외형으로’와 ‘펫 동행 해제’로 되돌립니다.
- 골드·재료·스킬 배치·장비·공격 범위·대미지는 바뀌지 않습니다. 효과가 커져도 실제 피격 판정은 동일합니다. 적의 위험 경계는 큰 효과 위에서도 다시 표시합니다.
- 구매와 장착은 기존 저장/백업 경로를 사용합니다. 저장 실패 시 기존 상태로 되돌립니다. 기존 저장 형식 2와 최대 100레벨을 유지합니다. 기존 저장을 읽거나 상점을 둘러보기만 할 때 구매 데이터를 새로 쓰지 않습니다.
- Wi-Fi 협동과 개인전에도 외형/펫 식별자를 전달합니다. 개인전의 능력치 보정은 그대로입니다. 프로토콜 **10**이므로 파티원 모두 같은 버전으로 업데이트합니다.
- 필요한 외형과 펫만 준비하고 캐시를 제한합니다. 필수 원화를 읽지 못한 전투는 대기하고 재시도할 수 있습니다. 화면 효과 줄이기 설정과 원격 효과 장식 상한을 적용합니다.

## 결제 연결 시 이어갈 지점

`premium.js`의 상품 ID/SKU, 9,900원 표시, `CONFIG`, `purchase`, `equip`이 연결 경계입니다. 현재 설정은 `mode: 'test'`, `allowTestPurchases: true`, `paymentProvider: null`입니다. 영수증에는 상품 ID와 SKU, `mode: 'test'`, `charged: 0`을 명시합니다.

실결제 전환은 단순히 테스트 설정을 켜는 방식으로 처리하지 않습니다. 추후 요청 시 Play 상품 등록/결제 SDK, 인증된 서버의 구매 토큰 검증과 중복 처리, 구매 승인/복원·환불·보유권 동기화를 구축하고, 검증된 보유권을 이 모델에 연결합니다. 로컬 테스트 영수증을 실제 유료 영수증으로 신뢰하지 않습니다. 테스트 구매분의 출시 전환 정책은 그때 명시적으로 정하며 현재 기록을 임의로 삭제하거나 청구하지 않습니다.

랭킹 서버 설정은 계속 `enabled: false`, endpoint/publicKey 빈 값입니다. 서버/DB와 집사 사절 원본은 수정하지 않습니다.

## 검수 범위

`premium.test.cjs`는 40상품의 구매/중복/직업 제한/해제/백업/손상 정리와 30외형의 동일 전투 결과를 확인합니다. `premium-art.test.cjs`는 최종 원화와 2,080개 셀의 경계/투명 데이터/출처를, `premium-presentation.test.cjs`는 실제 상점 조작과 30외형×9스킬·6동작/10펫/저장 재시작/작은 화면·확대 글자를 검사합니다. `premium-rendering.test.cjs`는 실제 이미지 디코딩·모든 모션 프레임·30효과·기본 공격과 9스킬의 실제 발동/렌더링 300건·4인 표시와 캐시/로딩 재시도를 검사합니다. 내부 `premium-lan.cjs`로 4개 화면의 실제 JSON 중계, 대기실 해제/재장착과 전투·투사체 외형 전달도 확인합니다.

원본 RGBA를 보존하여 포장하고, 전투 효과의 행 구분은 실제 원화의 투명한 간격에 맞춥니다. 출처 manifest의 `cells`/`rowCuts`와 런타임 소스 사각형을 기록하며, 셀 분할이 원화 전체를 겹침 없이 보존하는지도 검사합니다. 이동/공격 은행의 기준 발 위치와 몸 높이를 맞춰 외형 전환 시 크기·위치가 뛰는 현상을 줄입니다.

6직업별 대기·달리기·3단 공격의 실제 렌더 크기를 비교하고, 30벌의 6동작과 9스킬을 연속 재생해 `premium-motion-review.webm`으로 기록합니다. 4인 모두 같은 직업에 서로 다른 외형·펫을 장착한 경우도 별도로 표시하여 96MiB 캐시 상한을 확인합니다. 휴대폰 구매 버튼은 상품 목록을 끝까지 스크롤한 상태에서 실제 화면의 가림 여부까지 검사합니다.

최종 자동 검증·APK·공개 ZIP 결과는 완료 후 이 문서에 기록합니다. 실기기 장시간 FPS/발열, 실제 유료 결제와 Play 등록은 이 테스트 상점의 자동 검사에 포함되지 않습니다.

## 원화 포장 유지보수

`python3 tools/pack-premium-art.py --sources mapping.json --final`로 image_gen의 승인된 새 PNG를 포장합니다(Pillow 필요). 매핑은 시트 키와 로컬 PNG 경로의 JSON 객체입니다. 수정하지 않은 키는 기존 승인 WebP를 사용하고 원본 출처를 보존합니다. 픽셀을 수정하지 않고 RGBA가 같은지 확인하며, 실제 투명 간격에 맞춘 소스 구획을 기록합니다. 모든 75시트의 경계/투명도 검사를 통과해야 `--final`이 전체 manifest를 갱신합니다. 앱/CI 빌드에는 이 저작 도구나 원본 PNG가 필요하지 않습니다.
