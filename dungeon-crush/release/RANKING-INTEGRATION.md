# 랭킹 메뉴와 추후 서버 연결

이번 버전은 사용자 지시에 따라 **서버 연결 없이 메뉴·기능만** 제공합니다. 외부 프로젝트·DB·서버를 생성하거나 변경하지 않았습니다. 기본 전역 provider는 null이며 네트워크 조회/업로드·계정 생성·식별자 발급을 하지 않습니다.

## 현재 동작

- 메인 메뉴, 마을, 캐릭터/콘텐츠/던전 선택 화면에서 ‘랭킹’을 엽니다.
- ‘전체 랭킹’은 ‘서버 연결 전’으로 안내하며 가짜 플레이어/순위를 넣지 않습니다.
- ‘내 기록’은 이 기기의 6개 캐릭터 저장 데이터를 읽습니다. 데이터를 쓰거나 기존 장비/골드/성장을 변경하지 않습니다.
- 종목: 현재 전투력(동률이면 레벨), 성장(누적 경험치), 균열(최고 층, 싱글·파티 포함), 원정(누적 정복 횟수), 개인전(승수, 동률이면 승률).
- 같은 기준 값은 공동 순위(1, 1, 3)입니다. 같은 순위 내 표시 순서는 직업 ID로 고정합니다.
- 직업 필터, 상세보기, 선택 캐릭터 요약, 새로고침, 뒤로가기/키보드 조작을 제공합니다.

## 서버 조회 어댑터

서버가 준비되면 앱 초기화 후 아래 인터페이스를 연결합니다. 공개 배포된 앱의 기본 상태는 미연결입니다.

```js
DungeonRankingUI.setProvider({
  async load({ metric, cls, limit, signal }) {
    // 인증/HTTPS/서버별 API 호출은 구현 시 추가합니다.
    // 서버가 계산한 전역 순위와 공개 프로필만 반환합니다.
    return { entries: [], total: 0, updatedAt: '2026-11-11T00:00:00Z' };
  }
});
```

`metric`: `power | growth | rift | clears | arena`, `cls`: -1(모든 직업) 또는 0~5, `limit`: 50, `signal`: AbortSignal.

응답 항목: `{id, name, cls, level, rank, value}`. `rank`는 서버가 해당 종목/직업 조건에 대해 계산한 1 이상의 순위이며 오름차순입니다. 같은 rank를 사용할 수 있습니다. `level`은 1~100, `value`는 0~1e12, `id`는 중복 없는 문자열, name은 공개 표시 이름입니다. 성장은 value에 누적 경험치를 반환합니다. total은 전체 해당 조건 기록 수이며 entries 수 이상이어야 합니다.

UI는 응답 크기/형식/직업/순위/값을 검사하고 이름은 textContent로 표시합니다. 직업/종목을 바꿨거나 창을 닫은 뒤 도착한 응답은 무시합니다. 조회는 10초 후 오류와 재시도를 안내합니다. 빈 기록/연결 실패/새로고침 상태를 구분합니다. 테스트의 서버 데이터는 테스트 안에서만 만들며 앱에 샘플 이용자를 포함하지 않습니다.

## 서버 구현 시 별도로 필요한 작업

실제 계정 인증·권한·서버에서 검증한 기록·중복 제출 방지·요청 제한·시즌 규칙·개인정보 안내 변경이 필요합니다. 현재 오프라인 저장 수치를 그대로 신뢰하여 전역 랭킹에 올리는 API는 만들지 않았습니다. 클라이언트 코드에 운영 비밀 키를 넣지 않습니다.
